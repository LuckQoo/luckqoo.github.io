# AI Chat Worker

The Worker validates Clerk session JWTs against the production Clerk JWKS and accepts requests only from the EPOCH storefront. A separate D1 database tracks hashed user identifiers and UTC daily usage; conversation content is sent to the model but is not stored by this Worker. The initial limits are 10 successful replies per user and 50 globally per UTC day. No credentials belong in Git.

The dashboard-managed Worker `epoch-ai-chat-backend` requires a D1 binding named `DB` (initialize it using `schema.sql`), a `MODEL_URL`, and encrypted `MODEL_API_KEY` and `TAVILY_API_KEY` secrets. Supported model hosts are explicitly allowlisted in `src/index.js`. The Hugging Face Space requires a matching dedicated model secret, separate from its repository-write token, and access controls for its training interface.

Install dependencies with `npm ci`, run `npm test`, then bundle `src/index.js` as an ES module for dashboard deployment. Dashboard bindings and secrets must be preserved when deploying. When users enable web search, the Worker sends only their current question (at most 400 characters) to Tavily's basic search, passes bounded snippets to the model, and returns validated source links. Search errors are reported instead of silently presenting an unsourced answer. Search attempts are limited globally to 30 per UTC day, or at most 930 in a 31-day month; the chat's existing limits also apply. On the free plan, search stops if credits are exhausted. Search results are untrusted external content and answers can still be inaccurate. No conversation or search query is stored by this Worker, but queries are sent to Tavily and conversation context is sent to the model provider.
